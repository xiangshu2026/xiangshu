## 三、这个项目最核心的东西：六层审计模型

做这个项目最大的收获不是代码，是一套**发现问题的方法**。它分了六层，而且**每一层都以为到底了，结果还有下一层**：

| 层 | 查什么 | 什么时候才想到查 |
|---|---|---|
| ① 实现是否正确 | 代码有没有写错 | 第一轮就在查 |
| ② 实现是否忠于规则 | 代码有没有按规则执行 | 第 25 轮都在查 |
| ③ **规则本身是否成立** | 规则有依据吗 | **第 28 轮才开始查** |
| ④ **规则之间的相对权重是否有依据** | 为什么冲是 6 不是 3？ | **第 32 轮才被指出** |
| ⑤ 子维度是否扫全 | 层内部还有没扫到的维度 | 第 20 轮 |
| ⑥ 代码路径是否分裂 | 同类项走了不同函数 | 第 22 轮 |

### 七类错误的完整账

33 轮对抗里，写引擎的一方输了 20 条。错误分类：

| 类型 | 次数 | 例子 |
|---|---|---|
| 漏项（维度没写全） | 4 | 漏合月支 / 漏刑害破 / 漏藏干 / 漏贵人宫位 |
| 方向反了（符号错） | 3 | 伏吟加分 / 合不算五行 / 冲按五行翻转 |
| 重复计分（违反自己立的规矩） | 4 | 三支成局却拆成两个半合 / 合与破双计 / 藏干与合化双计 / 冲贵人与冲年支双扣 |
| 双标（同一原则两处不一） | 2 | 冲用宫位合用五行 / 合贵人有加分冲贵人没有 |
| 层未扫 | 2 | 日层完全没扫 / 时辰层第五子维度没扫 |
| 路径分裂 | 2 | 合类两套系数 / 又写一遍公式 |
| 规则无依据 | 1 | 成局系数硬编码日支 1.0 |

**四类里三类都是「写过正确原则，但在别处没照做」。**

### 三条去重铁律

| 铁律 | 内容 |
|---|---|
| **A** | 同一对地支的多个关系 → **取烈度最高一条**（如丑未既冲又刑，只记冲） |
| **B** | 同一事实的多种说法 → **只计一次**（时支与年支同字且为贵人宫时，只计一次） |
| **C** | 关系成立本身**不计分**（合贵人 +3 后不再加「有合」分） |

### 最该记住的一句话

> **「知道规律」不等于「执行规律」。**

第 29 轮总结出「我修的是这一处的合，不是合这个类」，**第 30 轮立刻又犯了同类遗漏**。

所以真正的改进不能是「再承诺一次收齐」——

1. **在数据结构上让同类项聚在一起**（`REL_LEV` 里 he / banhe / gonghe / chengju 相邻 + 注释「这四个必须同规则」）
2. **加守卫测试**

**靠承诺没用，靠结构有用。**

## 四、工程实现：入口收敛

评分逻辑最初是「加法式」——每加一个维度就写一个 if 分支，还要记得乘系数、定符号、写注释（四件事）。错误率随维度数线性增长。

后来改成「收敛式」：**所有计分必须经过 `addRel()`**。

```
加法式：写 if 分支 → 记得乘系数 → 记得定符号 → 记得写注释    （四件事，会漏）
收敛式：只加参数                                              （一次机会）
```

而且「收敛」本身也分两层：

| 层次 | 做法 | 缺陷 |
|---|---|---|
| 函数收敛 | 抽出统一公式 `juScore()` | 仍要靠清单去改所有调用点，会漏 |
| **入口收敛** | 所有计分必须经过 `addRel()` | **不存在「忘了改」** |

验证方式也随之改变：不用列清单，直接 `grep 'hs +='` 看它出现在哪——只在 `addRel` 里就对了。**把人工检查法固化成测试**（10 处断言直接读 `xs-gacha.js` 源码，检查「不存在第二份公式」这类结构性质）。

> **可推广的原则：不要靠「记得调用」，要靠「绕不过去」。**

## 五、数值来源声明（重要）

> 本引擎的「关系烈度表」（冲 6 / 刑 3 / 害 2 / 破 1 / 合 2 / 伏吟 1.5 / 成局 4）与「宫位系数表」（日 1.0 / 月 0.6 / 时 0.5 / 年 0.4）：
> - **次序**（冲 > 成局 > 刑 > 合/半合/害 > 伏吟 > 破；日 > 月 > 时 > 年）**有传统依据**；
> - **具体比值是估定的，非古籍原文**；
> - 因此**绝对分数只有相对意义**（用于排序），不应被当作「准确值」；
> - **有定性依据的结论（酉时吉、卯时凶）比分数更可靠**。

## 五、农历日期怎么选（已修）

**原来的问题**：农历模式还在用浏览器的**公历日期控件**——弹出的日历没有农历标注，想选「农历十月二十」只能靠「把 10-20 理解成农历制」硬猜，闰月还得单独一个下拉，很反直觉。

**现在**：历法切到「农历」后，日期变成**三个独立下拉**：

| 控件 | 内容 |
|---|---|
| 年 | 1900 ~ 2020+ |
| 月 | 正月 / 二月 / … / 十月 / 冬月 / 腊月（中文月名） |
| 日 | 初一 / 初二 / … / 三十 |

- 闰月改成勾选框「勾选＝闰月（如闰四月）」，不再混在日期里
- 选完立刻**回显对应公历**（如「对应公历：1990-06-15」），方便核对
- 切回「公历」时自动恢复原日期控件
- 非法农历（如 2020 年没有闰六月）给中文提示，不崩


## 六、十二时辰改五维综合计分（修掉「午时被判凶」）

**原 bug**：2026-10-21 午时（11:00–12:59，戊午）被判「凶 26 分」，但戊土是样本第一用神——判反了。

**根因**：时辰判档**只看时值神黄道/黑道一个维度**（权重 ±2×12 = ±24，压倒一切），命盘因素只作备注。于是午时因「天刑黑道」被判凶；更糟的是**申时（冲日支寅，最忌）反而被判吉 74 分**——与自己 battle 文件里「冲日支最忌」的逻辑打架。

**修法：五维综合计分**（与日层同一把尺子，50 + 合计×3.0，档位由分数决定）

| 维度 | 权重 |
|---|---|
| 时值神黄道/黑道 | ±2（传统「时家黄道」分量低于命盘因素——扶抑优先） |
| 时干对你的十神 | ±3（印比助身、官杀克身） |
| 时支五行合不合喜用 | ±3 |
| 时支与命局四支的冲合 | **冲日支 −8（最重）** / 冲月支时支 −2 / 合年支贵人 +3 / 合时支日支 +2 / 伏吟 +1 |
| 时支与当日日支关系 | 冲 −2 / 合 +2 |

**2026-10-21 修正前后对比**：

| 时辰 | 修正前 | 修正后 | 说明 |
|---|---|---|---|
| 午 11–13 | **凶 26** | **平 50** | 戊土偏印 +2、合年支未贵人 +3，但午火非喜用 −3、天刑黑道 −2 |
| 申 15–17 | 吉 74 | **平 50** | 冲日支寅 −8，压住了黄道+比肩+喜用+合时支的加分 |
| 未 13–15 | 凶 38 | **吉 65** | 己土正印 +3、土合喜用 +3、伏吟贵人 +1 |
| 酉 17–19 | 吉 86 | **吉 71** | 天德黄道 + 金合喜用 + 合当日辰 |

**最佳时辰**改为按综合分取前三（不再只筛黄道时辰），10-21 为：**酉时71 · 未时65 · 辰时56**。

**顺带修掉的陈旧文案（6 处）**：气势分公式说明仍是旧的 ×4.5（应为 ×3.0）、时辰说明仍写「按值神黄道/黑道判」（应为五维综合）——`xs-gacha.js`、`xs-interp.js`、`index.html`×4、`app.js`×2、README。

**测试**：344 项全过（旧断言「时辰吉凶按值神」「吉时全部为黄道」「最差时辰必为黑道」全部按新逻辑改写，因为现在档位由综合分决定、最差时辰可能是命盘凶时而非黑道）。单文件 887 KB。


## 八、农历输入的生日现在能生效（修掉「不同人算出同样结果」）

原 bug 1 —— 农历生日被忽略：当日运势 / 避灾 / 未来 7 天 都走 dlBirth()，而它只读公历框 bzDate，不看农历三下拉。所以用农历填生日时，实际拿的还是公历框里的旧值 → 两个人算出完全一样。而「排盘」走的是 baziOptions()（它认农历）——所以排盘结果是对的、每日运势是错的。

修法：dlBirth() 改为与 baziOptions() 一致地识别农历，农历时读三下拉并带上 calendar: 'lunar'。

原 bug 2 —— 中和盘「喜用神取不到」：八字中和（五行均衡）时，原代码把 favor 留空。后果是这类盘的「今日之气与喜用」项 365 天恒为 0，个人项少一维，结果被拉平。

修法：按传统调候取用——夏月取水（金辅）、冬月取火（木辅）、春月取土（金辅）、秋月取火（木辅）、四季月取木（水辅）。

修后实测（样本 A vs 样本 B 农历2004六月廿八 09:20）：两人档位相同 37.5% → 25.5%；平均分差 15.7 → 21.5 分；样本 B「喜用项恒为 0」从 365/365 天变成 0/365 天。

最近 4 天实际对比：10-18 我 20(凶大) / 友 49(平)；10-19 我 50(平) / 友 80(大吉)；10-22 我 71(吉大) / 友 47(平)；10-23 我 65(吉中) / 友 26(凶大)。


## 八、气势分不再出现 0 分（系数与权重不同步的 bug）

原 bug：10-30 显示「0 分」。

根因：气势分公式是 50 + 各项合计 × 4.5，但那是权重加倍前的系数。权重加倍后合计范围变成 −16 ~ +15.5，而 ×4.5：
- 合计 −12 → 50 − 54 = −4 → 被截断成 0 分
- 合计 +12 → 50 + 54 = 104 → 被截断成 100 分

两端都被压平，0 分和 100 分都是被 clamp 出来的假值——真实分数信息丢了。全年有 8 天是 0 分。

修法：系数 4.5 → 3.0（让 ±16 映射到 50±48，落在 0~100 内），档位阈值同步重定为 ≥78 大吉 / ≥64 吉 / ≥35 平 / ≥22 凶 / <22 大凶。

结果：10-30 从 0 分变成 14 分（凶·大）；全年 0 分的天数从 8 天变成 0 天；全年最低分 5（合计 −15）。一年分布：平 58% / 吉 18% / 凶 15% / 大吉 5% / 大凶 4%。


## 九、两个人的每日运势不再雷同（提高个人项权重）

原问题：和样本 B的每日运势看着一模一样。实测 365 天里档位相同 61.4%、分数只差几十分。

根因：每天的分数由两类项构成——

| 类型 | 项目 | 权重 |
|---|---|---|
| 共同项（对所有人相同） | 值神黄道/黑道、建除十二神、吉神凶煞 | 合计 ±6 |
| 个人项（每人命盘不同） | 日干对你的十神、今日之气合不合喜用、日支是否冲合你 | 合计 ±5（原） |

共同项占了一半以上，把所有人的分数都往同一个方向拉，个人差异被淹没。

改法：个人项权重加倍（十神 ±3、喜用 ±3、日支冲合 −3/+2.5），共同项不动；同时上移档位阈值保持分布。

结果：两人档位相同 61.4% → 30.1%；分数相同 5.2% → 1.6%；平均分数差 ~10 分 → ~20 分。

档位阈值同步调整（权重变了，分数范围从 ±10 变成 ±18）：≥92 大吉 / ≥72 吉 / ≥34 平 / ≥10 凶 / <10 大凶，一年分布回到 平 44~56% / 吉 16~20% / 凶 23~27% / 大吉 5~6% / 大凶 5~6%。

注意：样本 B的盘「喜用神取不到」（八字中和·调候），所以他的「今日之气」项恒为 0，个人项少一项——这是真实命盘差异，不是 bug。


## 八、判档与气势分完全一致（修掉「12 分判平」）

原 bug：判档用「四项计数」、气势分用「加权求和」，两套逻辑各算各的——所以出现 12 分（合计 −8.5）判「平」这种自相矛盾。实测 365 天里有 45 天「判平但分数极端」。

修法：分数唯一决定档位（气势分本来就是各项计分的真实汇总，档位跟着它走才自洽）：

| 档位 | 分数区间 | 一年占比 |
|---|---|---|
| 大吉 | ≥ 86 | 3.6% |
| 吉 | 68 ~ 85 | 17.8% |
| 平 | 33 ~ 67 | 54.8% |
| 凶 | 12 ~ 32 | 21.1% |
| 大凶 | < 12 | 2.7% |

「四项计数」保留为依据说明（rule 文字），但不再单独决定档位。

校准后 365 天：平 54.8%（200 天）/ 凶 21.1% / 吉 17.8% / 大吉 3.6%（13 天）/ 大凶 2.7%（10 天）——「平」是日常常态，极端档罕见。

新增守卫测试：档位与气势分完全一致（无低分判平矛盾）——遍历 120 天验证 score 与 level 的映射关系，以后谁改了阈值不同步就会立刻报错。


## 九、判档分布已校准（大吉大凶不再泛滥）

原问题：大凶 10.4%（一年 38 天）、大吉 6.3%（一年 23 天）——「大凶」这种词一年出现 38 次就不叫大凶了。

根因：旧规则「黄道+成开+吉神≥凶煞 → 大吉」、「黑道+闭破 → 大凶」，单项达标就封顶，门槛太松。

改法：四项计数法（传统择日本就是多项共振才成极端）

| 项 | 吉的条件 | 凶的条件 |
|---|---|---|
| 一、值神 | 黄道 | 黑道 |
| 二、建除 | 成 / 开 | 破 / 闭 |
| 三、吉煞差 | 吉神 − 凶煞 ≥ 3 | 凶煞 − 吉神 ≥ 3 |
| 四、数量 | 吉神 ≥ 5 | 凶煞 ≥ 6 |

net = 吉项数 − 凶项数（−4 ~ +4）：≥+4 大吉 / +3 +2 吉 / +1 0 平 / −1 平 / −2 −3 凶 / ≤−4 大凶。

校准后一年 365 天分布：平 172 天（47.1%）/ 吉 118（32.3%）/ 凶 48（13.2%）/ 大吉 17（4.7%）/ 大凶 10（2.7%）。

顺带修掉一个真 bug：抽卡时运 与 八字当日运势 两个引擎判档不一致（60 天里 30 天不同）。已统一——判档规则只在 xs-daily.js 维护一份，抽卡引擎调 judgePure() 复用，个人「日辰冲命降一档」由抽卡侧自己补。现在 60 天 100% 一致。
